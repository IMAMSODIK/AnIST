# Fix: Deduplikasi Aplikasi pada Evidence Implementasi Sistem

## Masalah
Saat ini `EvidenceService::updateRealisasi()` melakukan **SUM(realisasi)** dari semua ai_results yang valid. Jika 2 evidence untuk aplikasi yang sama di-upload (misalnya UAT Klaim Kacamata + Berita Acara Go Live Klaim Kacamata), realisasi = 2 padahal seharusnya = 1 karena tetap 1 aplikasi yang sama.

## Solusi
AI akan mengembalikan daftar nama aplikasi (`applications[]`) yang ditemukan di setiap evidence. Laravel melakukan **COUNT(DISTINCT aplikasi)** dari semua evidence, bukan SUM(realisasi). Hanya berlaku untuk measurement "Implementasi Sistem Digital".

---

## Langkah Implementasi

### 1. Migration: Tambah kolom `applications` di tabel `ai_results`
- Buat migration baru: `alter_ai_results_add_applications`
- Tambah kolom `applications` (JSON, nullable) untuk menyimpan array nama aplikasi yang teridentifikasi AI
- Contoh isi: `["Klaim Kacamata", "Mobile Banking"]`

### 2. Update `AiResultDTO`
- Tambah property `$applications` (array)
- Update `fromAiResponse()`: baca field `applications` dari response AI
- Update `toArray()`: sertakan `applications` untuk disimpan ke DB

### 3. Update `AiResult` Model
- Tambah `applications` ke `$fillable`
- Tambah cast: `applications => 'array'`
- Tambah accessor: `getApplicationsArrayAttribute()` (aman parse JSON)

### 4. Update `PromptManager`
- **Update `getImplementasiSistemPrompt()`**: tambah instruksi kepada AI untuk:
  - Mengidentifikasi SEMUA nama aplikasi/sistem yang disebutkan di evidence
  - Mengembalikannya dalam field `applications[]`
  - Menormalisasi nama aplikasi (gunakan nama utama, bukan variasi)
- **Update output format**: tambah field `applications` (wajib untuk Implementasi Sistem, opsional untuk lainnya)
- **Update `getOutputFormat()`**: tambah field `applications` di contoh JSON

### 5. Update `ResponseValidator`
- Tambah validasi: jika measurement adalah Implementasi Sistem, field `applications` harus ada dan berupa array
- Normalisasi: pastikan `applications` selalu berupa array (kosong jika tidak ada)
- Update `normalize()`: handle field baru `applications`

### 6. Update `EvidenceService::updateRealisasi()` ← **Perubahan Inti**
```
if (implementasi_sistem) {
    // Kumpulkan semua nama aplikasi dari semua ai_results valid
    // Flatten, unique, hitung jumlahnya
    totalRealisasi = COUNT(DISTINCT applications)
} else {
    // Logic lama: SUM(realisasi)
    totalRealisasi = SUM(realisasi)
}
```
Tambah helper method `isImplementasiSistem(Measurement $measurement)` untuk mengecek tipe measurement.

### 7. Update `InsightService::allEvidenceContext()`
- Sertakan informasi `applications` di setiap evidence block
- Gemini bisa merujuk nama aplikasi spesifik dalam narasi insight

### 8. Fix Bug: `UploadService::deleteUpload()`
- Setelah menghapus upload + aiResult, **rekalkulasi realisasi** untuk measurement/quarter/year yang bersangkutan
- Ini menutup celah: saat ini penghapusan evidence tidak memperbarui realisasi yang sudah teragregasi

## Alur Baru (Implementasi Sistem)

```
Upload "UAT ESS Klaim Kacamata"
  → AI analisis → ai_results: { applications: ["Klaim Kacamata"], realisasi: 1 }
  
Upload "Berita Acara Go Live Klaim Kacamata"
  → AI analisis → ai_results: { applications: ["Klaim Kacamata"], realisasi: 1 }
  
updateRealisasi():
  → applications terkumpul: ["Klaim Kacamata", "Klaim Kacamata"]
  → unique: ["Klaim Kacamata"]
  → COUNT = 1 ✅ (bukan SUM = 2)
```
