## FASE 1 — Perbaikan Bug Kritis (prioritas tertinggi)

### 1.1 `ScoreCalculator::mapToScoreBand` — bug banding gap (paling kritis)
- **Masalah:** Band pakai `max => X.99`, sehingga achievement di rentang terbuka `(99.99, 100)` (mis. 99.997) tidak masuk band mana pun → `return 0` → KPI ~100% diskor 0.
- **Perbaikan:** Ubah `scoreBands` jadi half-open `[min, nextMin)` — band diuji dengan `$achievement >= min && $achievement < nextMin`, band terakhir `[0, 60)`. Eliminasi semua gap floating-point. Tambah band `>= 120` di atas.

### 1.2 Double-hash password `RegisterController` + `User`
- **Masalah:** `User` punya cast `'password' => 'hashed'`, DAN `RegisterController` memanggil `Hash::make()`. Meski Laravel `hashed` cast toleran, ini redundan & rapuh.
- **Perbaikan:** Hapus `Hash::make()` di RegisterController, andalkan cast (seirama dengan konvensi Laravel 12). Hapus import `Hash` yang tak terpakai.

### 1.3 `DashboardService::getConfidenceDistribution` — bucket tidak menutup
- **Masalah:** confidence tepat `0` (hasil AI gagal) tak masuk bucket mana pun; juga tak di-scope year/quarter.
- **Perbaikan:** Ubah bucket `low` jadi `<= 50` (termasuk 0), `medium` `(50, 80)`, `high` `>= 80`. Tambah parameter `?int $year, ?string $quarter` agar konsisten dengan window dashboard lainnya; sambungkan dari DashboardController.

### 1.4 `DashboardService::getWidgets` — label `average_score` menyesatkan
- **Masalah:** key `average_score` diisi `avg('achievement')` (persen), bukan score.
- **Perbaikan:** Tambah key `average_achievement` (dari `avg('achievement')`) dan `average_score` (dari `avg('score')`) agar dashboard card bisa menampilkan angka yang benar. Update `dashboard.blade.php` widget untuk pakai key yang tepat.

### 1.5 `KPIService::calculateAchievement` — 'lower is better' saat realisasi=0
- **Masalah:** realisasi=0 (ideal untuk "lower") menghasilkan `target*100` (mis. 500%) yang ter-cap 120.
- **Perbaikan:** Formula 'lower is better' yang lebih wajar: `100 + ((target - realisasi)/target)*100` saat `realisasi <= target`, dan `max(0, 100 - ((realisasi-target)/target)*100)` saat `realisasi > target`. Cap achievement di 120 di tingkat service (konsisten dengan band).

### 1.6 `KPIService::getOverallScore` — sum tak ternormalisasi
- **Masalah:** menjumlahkan weighted score, hanya bermakna jika total weight = 100.
- **Perbaikan:** Tambahkan normalisasi: rata-rata tertimbang `(SUM(score) / SUM(weight/100*base))` atau, lebih sederhana dan andal: `SUM(score) / SUM(max_possible_weight) * 100`. Saya akan pakai pendekatan weighted average berbasis achievement agar overall score selalu di 0–120 dan tidak bergantung pada total weight = 100.

### 1.7 `GeminiService::sendWithRetry` — undefined variable saat `max_retries=0`
- **Perbaikan:** Inisialisasi `$response = null` di awal agar `return $response` di akhir aman meski loop tak jalan. Sekalian pindah API key dari query string ke header `x-goog-api-key` (lebih aman, tidak bocor di log URL).

### 1.8 `PromptManager` keyword match `' ai '` yang rapuh
- **Perbaikan:** Gunakan regex word-boundary `\b(ai)\b` alih-alih `str_contains` ber-spasi, agar nama "AI Implementation" cocok.

## FASE 2 — Mengaktifkan Fitur yang Orphaned

### 2.1 Wire `BatchProcessEvidenceJob` (bulk reprocess)
- Tambah menu/aksi di `uploads/index.blade.php`: tombol "Process Pending" + filter year/quarter → route `POST /uploads/batch-process` → controller dispatch `BatchProcessEvidenceJob::dispatch(...)->onQueue('evidence')`. Sertakan flash message "N uploads queued".

### 2.2 Wire `CalculateKPIJob` (recalculate async)
- `KPIMonitoringController::recalculate` saat ini sinkron. Ubah agar dispatch `CalculateKPIJob::dispatch($quarter, $year)->onQueue('default')` + flash message, lalu redirect. Tetap pertahankan fallback sinkron via parameter `?sync=1` bila perlu.

### 2.3 Throttle login (brute-force protection)
- Tambah middleware `throttle:5,1` pada `POST /login` di `routes/web.php`.

### 2.4 Form Request: uniqueness target
- `StoreTargetRequest` & `UpdateTargetRequest`: tambah rule unique gabungan `(measurement_id, year, quarter)` sesuai unique constraint di migration, agar duplikat tertangkap di validasi (bukan ditimpa diam-diam oleh `updateOrCreate`).

### 2.5 Audit trail saat registrasi
- `RegisterController::register`: catat `AuditTrail` (`action: 'register'`, `model_type: User`) agar konsisten dengan seluruh operasi create lainnya.

### 2.6 `LoginController::logout` route name
- Ganti redirect `'/login'` → `route('login')`.

## FASE 3 — Export Reports (PDF + Excel/CSV)

### 3.1 Dependency
- `composer require barryvdh/laravel-dompdf phpoffice/phpspreadsheet`. (Saya akan jalankan `composer require`.)
- Daftarkan provider/alias dompdf sesuai instruksinya (Laravel auto-discover biasanya cukup).

### 3.2 Service baru `app/Services/ReportExportService.php`
- `exportPdf(year, quarter)` → render `reports/pdf.blade.php` via `PDF::loadView(...)`, return `Download` response.
- `exportExcel(year, quarter)` → bangun Spreadsheet via PhpSpreadsheet, return download `.xlsx`.
- `exportCsv(year, quarter)` → native CSV tanpa PhpSpreadsheet (ringan).

### 3.3 Controller & Routes
- `ReportController`: tambah `exportPdf`, `exportExcel`, `exportCsv`.
- Routes: `GET /reports/export/pdf`, `/export/excel`, `/export/csv` (semua accept `?year=&quarter=`).

### 3.4 View
- `reports/pdf.blade.php` (layout cetak: kop, periode, tabel report, total, ttd).
- Tombol export (PDF / Excel / CSV) di `reports/index.blade.php`, mempertahankan filter year/quarter.

## FASE 5 — Build Aset & Persiapan Database

### 5.1 Enable driver pdo_mysql (bantuan diagnostik)
- Saat ini `php artisan migrate:status` gagal: `could not find driver`. Saya akan:
  - Lokasi `php.ini` CLI yang dipakai (`php --ini`), identifikasi baris `;extension=pdo_mysql` / `;extension=pdo_mysql` (dan `mysqli`, `mbstring`, `fileinfo`).
  - **Anda yang meng-uncomment** (saya akan tunjukkan persis baris mana), karena mengubah php.ini di luar proyek adalah perubahan sistem yang butuh konfirmasi Anda. Setelah itu saya jalankan `php artisan migrate --seed`.

### 5.2 `npm run build`
- Jalankan `npm run build` untuk menghasilkan `public/build/` (manifest + compiled css/js) agar UI ber-style tanpa dev server. Verifikasi manifest ada.

### 5.3 Smoke test
- `php artisan route:list` (pastikan semua route baru terdaftar).
- `php artisan config:clear`.
- Setelah DB up: `php artisan migrate:fresh --seed` (opsional, hati-hati data) untuk memverifikasi skema + seeder.
- Jalankan queue worker sekali (`php artisan queue:work --once`) untuk memastikan job tidak crash saat bootstrap.
